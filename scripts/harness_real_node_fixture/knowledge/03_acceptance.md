# 真实节点参数传递的验收方法

适用范围：隔离测试空间的接口检查和摘要生成流程。内容版本 2026-10-12 v1。目标是验证智能体能读取业务知识、选择真实插件、正确设置参数，并将实际输出传到下一节点。

## 三种结果分别报告

生成和校验通过，只说明流程结构与字段符合契约。mock 调试通过，只说明模拟路径能走通。真实 HTTP 调试通过，才说明 Engine 能访问测试服务、执行插件并传递实际参数。这三项不能互相代替。

知识库检索成功也分两层：BKAIDev 检索测试命中知识卡，不等于 Agent 已绑定并使用该知识库，更不等于 BKFlow Knowledge Router 的空间绑定已完成。要查看实际检索工具调用、命中文档和生成结果。

## 正常组与降级组

正常组输入 E2E-A、alpha、healthy，预期摘要 E2E-A | alpha | healthy | 12 ms。降级组输入 E2E-B、beta、degraded，预期摘要 E2E-B | beta | degraded | 850 ms。同一流程只改输入，不手工改节点或写死下游值。

对每组先单步检查查询节点，再单步检查摘要节点，确认都是真实执行。全局调试须另满足该环境的真实执行权限和审批要求；如果被拦截，应记录阻塞，不用 mock 结果冒充全局真实调试。

## 参数证据

1. 第一节点输出 data.received 等于本次用户输入，data.request_id 是本次新生成的值。
2. 第二节点实际输入中的五个字段等于第一节点 data 对应字段，其中 source_request_id 等于第一节点 request_id，latency_ms 保持数字。
3. 第二节点输出 data.received 与其实际输入一致，summary 随正常组和降级组变化。
4. 最后展示的实际输入和流程最终输出均等于第二节点返回的 summary。
5. 两次服务请求记录与调试节点对应；不能把同名节点的旧历史或另一个快照拼成一次成功。

本测试接口是无状态回显与计算服务，source_request_id 是用于交叉核对的关联值，不是防伪凭证。仅有接口回包不能证明模型没有写死数据，必须结合不同输入的两次运行和节点输入记录。

## 知识闭环

把失败分为检索没命中、选错插件、Schema 契约不一致、参数表达式未渲染、类型错误、网络或授权失败。缺少字段说明或使用例子时补知识卡；Schema 和运行代码矛盾时修代码，不能用知识卡掩盖；模型明知字段却填错时保留失败案例做回归。

知识卡更新后先重新检索，再用同一句短需求生成新草稿，最后重复两组参数测试。保留知识文档 ID 和版本、命中片段、流程 ID、调试会话及真实请求记录。没有实际运行证据时，状态保持待验证。
