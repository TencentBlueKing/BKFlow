# V1.12.0 Release Notes

<!-- Change range: V1.8.1 / 148617a5ef02ea98f1271f37a1d376a5621455d1 to upstream/master / ce8eef6a4721b6f7a4119842e081c921d09e60ab. Summarizes merged changes, consolidates duplicates, and excludes features from unmerged branches. -->

This release summarizes the main additions, improvements, and fixes since V1.8.1.

### Added

#### Workflow design and version management

- [ Added ] Stage-based workflow design with draggable stages, jobs, and nodes, node parameter copying, and execution views for stages and subprocesses.
- [ Added ] Subprocess references with version selection, expandable nodes, and execution by iteration count or loop parameters.
- [ Added ] Looping subcanvas nodes with nested workflows, loop rules, variable references, and output configuration. Task details display subcanvas status, iteration records, and outputs.
- [ Added ] Workflow version management with drafts, automatically saved snapshots, history, publishing, rollback, and cleanup of expired automatically saved snapshots.
- [ Added ] Labels for workflows and tasks, with filtering, label trees, and reference counts.

#### Workflow debugging

- [ Added ] Global and single-step debugging with node selection, mocked results, failure injection, context editing, reset, termination, and history queries.
- [ Added ] Conditional gateway debugging with branch match results and gateway status in global runs.
- [ Added ] Separate debug result snapshots containing workflow configuration, node names, configured inputs, and executed inputs. Configuration changes can mark results for rerunning; tools support previewing and backfilling historical snapshots.

#### Plugins and variables

- [ Added ] Standard Operations open plugin V4 integration with categories, search, business version selection, and native forms, retaining V2/V3 compatibility. Open plugins support execution snapshots, synchronous execution, polling, callbacks, and cancellation.
- [ Added ] Multiple API plugin sources, access credentials, request users, and validation of category, list, and metadata APIs. BlueKing plugins support secondary authorization and usage scopes; plugin catalogs support scheduled synchronization and per-space enablement.
- [ Added ] Built-in assignment, notification, and Python code nodes; decision table import and export. System settings can restrict built-in plugins to selected spaces.
- [ Added ] Space variables and password variables with encrypted input, references, and masked display. Text inputs offer variable suggestions, dropdowns support remote data sources, and URLs support variable rendering.

#### Triggers and notifications

- [ Added ] Scheduled triggers and periodic tasks with cron expressions, timezones, and execution counts. Space settings control whether a workflow can have multiple scheduled triggers.
- [ Added ] Webhook events for workflow publication and task creation, callbacks, pause, resume, and revocation.
- [ Added ] Workflow HTTP callbacks on task success or failure, with delivery times, events, results, status codes, and responses in task details.

#### Tenancy, permissions, and credentials

- [ Added ] Single- and multi-tenant modes with tenant isolation for spaces, workflows, tasks, plugin catalogs, and internal module calls, retaining legacy single-tenant requests and resources.
- [ Added ] Tenant user components and personal center integration; modern platform APIs for notifications, approvals, and language preferences; user timezones saved with periodic schedules.
- [ Added ] Application, login session, Basic Auth, and custom credentials with usage scopes, encrypted storage, updates, and credential context for tasks and mock execution.
- [ Added ] SM4-GCM credential writes through `BKFLOW_CREDENTIAL_CIPHER=SM4`, with continued reading of historical AES ciphertext. Upgrade every credential reader and writer before enabling SM4.
- [ Added ] BlueKing PaaS KMS integration to decrypt sensitive configuration at process startup when the platform enables `BKPAAS_KMS_ENABLED=true` and supplies key files.
- [ Added ] Composite Tokens granting multiple resource permissions in one request while retaining single-resource requests. Workflows can bind BlueKing applications and accept calls using application credentials.

#### Gateway APIs and operational statistics

- [ Added ] Simplified JSON and A2Flow v2 workflow creation, protocol validation, plugin listing, and plugin form schema APIs.
- [ Added ] Gateway and SDK APIs for batch workflow deletion, version management, drafts and automatically saved snapshots, triggers, canvas layout, space variables, labels, plugin configuration, and task deletion.
- [ Added ] Workflow filtering by multiple IDs, labels, creator, and updater. Task filtering by status, ID lists, labels, source, and subprocess conditions, with expandable subprocess tasks.
- [ Added ] Workflow, task, and plugin statistics with historical backfill, scheduled aggregation, a separate statistics database, and BK-Vision dashboards for systems and spaces.

#### Checking and handling stalled tasks

- [ Added ] Checks for prolonged inactivity, lost execution or polling, and abnormal callbacks, with diagnostic cases and recovery subject to prechecks, permissions, and operation records.
- [ Added ] Unified settings for detection, duplicate execution checks, recovery, and alerts. These capabilities are disabled when neither new nor legacy switches are configured; existing legacy settings remain effective. Automatic recovery additionally requires allowed spaces and failure types. See the [switch and migration guide](../docs/guide/stuck_governance_switches.md).

### Improved

#### Usability and APIs

- [ Improved ] Typed space configuration forms with explanations, defaults, validation, reset, and configurable maximum Token lifetime.
- [ Improved ] Canvas dragging, node copying, subprocess highlighting, and execution details; direct navigation from task details to workflow editing. Embedded pages can control navigation buttons and canvas type.
- [ Improved ] Debug tasks are excluded from normal task lists and operational statistics by default but remain queryable by task ID. Enhanced input validation, workflow tree checks, and error messages.
- [ Improved ] HTTP nodes support JSON escaping. Plugin configuration and node details prioritize the corresponding plugin forms and actual execution data. Expanded bilingual API documentation and configurable help links by language and deployed documentation version.

#### Execution and troubleshooting

- [ Improved ] Python nodes run in separate subprocesses with timeouts, memory limits, and concurrency control. Common special return types, timezones, and special characters are supported, and outputs can be filtered before transfer.
- [ Improved ] Task and plugin tracing with custom attributes supplied at task creation or execution, helping correlate upstream and downstream logs.
- [ Improved ] Bounded retries for transient transport and HTTP 502–504 failures when preparing subtask snapshots; external calls run outside database write transactions and preserve tenant context.

#### Deployment and compatibility

- [ Improved ] Upgraded to Python 3.11 and Django 4.2, with bamboo-pipeline 4.0.6, bamboo-engine 3.0.7, and compatible Celery and Webhook dependencies, retaining subcanvas, loop, and task diagnostic capabilities.
- [ Improved ] Configurable packaging application identity and gateway name to preserve existing applications, module addresses, and keys. Legacy single-tenant platforms can set `BKFLOW_PLATFORM_API_MODE=legacy` for their existing notification, member selection, language, and approval APIs.
- [ Improved ] Consistent user timezone selection with invalid values ignored. New periodic schedules save the user timezone; edits preserve the existing timezone when it is omitted.

### Fixed

#### Workflow design and execution

- [ Fixed ] Missing node connections preventing saves, node copy or selection problems, missing stage rendering, and stale return-node data on conditional branches.
- [ Fixed ] Subprocess task callbacks, interference between nested loop counts, lost canvas state after subprocess switches, and incorrect subprocess icons or names.
- [ Fixed ] Duplicate publication, version calculation, incorrect versions when copying workflows, and inconsistent subprocess references after rollback.
- [ Fixed ] Failed nodes that could not retry or skip, continuously loading node details, and serialization of special return values. Improved messages for memory errors while reading execution data.

#### Debug results

- [ Fixed ] Debug response formats, waiting state synchronization, residual node states after termination, and idle contexts incorrectly reported as terminated.
- [ Fixed ] Missing canvas positions in single-step runs, subcanvas debugging, and historical snapshot compatibility, including missing configured and executed inputs.
- [ Fixed ] Incorrect configuration change markers: external connection changes and new unexecuted nodes no longer invalidate results. Removing a mock clears node results and output variables and handles concurrent debug starts.

#### Plugins, variables, and parameters

- [ Fixed ] Open plugin default version selection, native forms in execution details, lost task parameters, and V4 polling configuration validation.
- [ Fixed ] Compatibility with selected inputs in legacy API plugins and legacy variable forms, dropdown multi-select labels, remote data credentials, and displayed node inputs.
- [ Fixed ] Output variables remaining after node deletion, variable updates reading old nodes, incorrect initial output values, and datetime range value types.

#### Permissions and security

- [ Fixed ] Permission checks for space administrators, workflow details and previews, mock execution, control settings, and PATCH saves, with stronger space and tenant ownership checks.
- [ Fixed ] Concurrent Token requests, renewal for the same resource, historical grant migration, and expired Token cleanup; tenant administrator authorization and historical snapshot ownership checks.
- [ Fixed ] Added a root identifier allowlist for Mako expressions and allowed-domain checks for HTTP nodes. Sensitive authentication headers are masked in plugin logs, and internal API response fields are restricted.

#### Pages, periodic tasks, and deployment

- [ Fixed ] Periodic task timezones and execution counts, rollback on trigger update failure, related data cleanup after workflow deletion, and omitted fields being overwritten during updates.
- [ Fixed ] Empty PaaS log queries, compatibility with older Engines lacking subprocess APIs or task labels, missing CSRF Cookies on initial visits, and blank pages caused by static image loading.
- [ Fixed ] Django 4.2 frontend routes returning HTTP 500, statistics database registration timing, and MySQL 5.7 connection compatibility. Required migration failures stop deployment; existing cache tables no longer block deployment.
- [ Fixed ] Global configuration loading paths and variable references, using the actual application identity and remotely supplied brand and version information.
