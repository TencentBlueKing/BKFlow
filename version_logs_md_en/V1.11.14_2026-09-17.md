# V1.11.14 Release Notes

<!-- Baseline: V1.11.13 / f759c8dcc11d4d9a134676154869501b0e9108ed. Compared with master 6098d9d0959e7e0f7d6996972df783118434e871, plus the packaging compliance changes in this PR. Create a new release tag after merging; do not move V1.11.13. -->

- [ Added ] Single- and multi-tenant configurations with tenant isolation for spaces, workflows, tasks, plugin catalogs, and internal module calls, while preserving legacy single-tenant requests and resources (#927).
- [ Added ] Tenant user components, personal center integration, platform user timezones, and tenant approval initialization; notifications and approvals support modern platform APIs (#927).
- [ Added ] SM4-GCM credential storage through `BKFLOW_CREDENTIAL_CIPHER=SM4`, with continued reading of historical AES ciphertext. Upgrade every credential reader/writer before enabling SM4 (#932).
- [ Improved ] Standard Smart packages use APP_Code `bk_flow`. A descriptor renderer and environment settings preserve existing cloud application identities, gateways, and module addresses (#932).
- [ Improved ] Platform protocol selection is independent of tenant mode. Modern single- and multi-tenant platforms use APIGW. Older single-tenant platforms can set `BKFLOW_PLATFORM_API_MODE=legacy` to retain ESB notifications, member selection, language preferences, and approvals (#932).
- [ Improved ] Unified timezone selection from internal headers, `blueking-timezone`, user cookies/sessions, and platform preferences; invalid values are ignored. New periodic schedules save the user timezone, and edits retain the existing schedule timezone (#932).
- [ Fixed ] Multi-tenant superuser authorization is restricted to existing logged-in users of the system tenant. Added a command to grant administration of a space in the user's own tenant (#932).
- [ Fixed ] Subtask snapshot preparation now retries transient transport and HTTP 502–504 failures within a limit, moves external calls outside write transactions, and preserves tenant context (#925, #927).
- [ Fixed ] Plugin synchronization scope, historical snapshot ownership, nested subprocess references, and deployment credential boundaries; required migration failures stop deployment (#927).
- [ Documentation ] Updated space settings and API plugin validation documentation to match merged behavior (#931).
- [ Documentation ] Added an English README, 94 English API documents, bilingual current release notes, and tenant error translations. Help links can be configured by language and deployed documentation version (#932).

Upgrade the Interface, every Engine, and the statistics database with their respective migrations. Verify and backfill tenant ownership before enabling multi-tenancy. Initialize approvals for `default` on modern single-tenant platforms. Existing cloud deployments must explicitly select their compatibility protocol and retain existing keys. See the [deployment guide](../docs/guide/release_compatibility_en.md).
