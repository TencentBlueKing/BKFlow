# 设计稿通用约束（评审沉淀）

> 来自 BKFlow 设计稿评审的**通用**要求，适用于所有 `prototype-design-mockup` 产出。  
> 主流程见 [SKILL.md](SKILL.md)；选图见 [visual-baseline-index.md](visual-baseline-index.md)。

出稿前与出稿后自检时，逐条核对。违反任一条 → 重出或先改线框/README 再出稿。

---

## 1. 现网视觉基准（强制）

| 约束 | 说明 |
|------|------|
| 必须查索引选图 | 每屏用 [visual-baseline-index.md](visual-baseline-index.md) 选 2–5 张 `output/playwright/bkflow-engine-admin/` 截图作 `reference_image_paths` |
| 布局跟截图，不跟想象 | 改造**已有页面**时，外壳/分区/Tab/侧栏结构以现网截图为准；新业务内容可加，但不得自创整页信息架构 |
| 深色顶栏 | 管理端顶栏为深色，禁止白顶栏 + 蓝下划线 Tab |
| 控件形态对齐 | 如输出参数用 `${x}` 方钮、Dialog 按钮居中、侧滑按钮左下等（见索引「易错对照」） |
| 脱敏 | 用户 `admin`，空间 `演示空间 (100)`；禁止照抄参考图真实账号/空间名 |

**反例**：任务节点详情被画成「左输出变量列表 + 右自定义卡片墙」——现网是「左节点列表 + 右 Tab（执行记录…）」。

---

## 2. 容器与遮罩（强制）

| 约束 | 说明 |
|------|------|
| Dialog 必须有遮罩 | 居中弹窗背后须有半透明遮罩，压暗画布/侧滑；弹窗本身保持亮白（对齐现网 Dialog） |
| 禁止伪造容器 | 不得发明产品中不存在的壳（如在「全局变量」浮层内自造左侧「变量列表/来源节点」导航），除非线框与现网代码均支持 |
| 以代码/截图校验容器 | 出稿前确认该面板在现网是 Dialog / `bk-sideslider` / 页内卡片中的哪一种；标题文案对齐现网（如「全局变量 > 编辑」） |
| **同系列弹框锁定** | 用户已确认某屏 Dialog/侧滑外壳后，同系列其余屏必须**像素级复用该壳**（见 §2.1），不得每屏重新发明弹框比例/阴影/底栏 |

**反例**：变量配置弹窗浮在画布上但无遮罩，背景与弹窗同亮。  
**反例**：屏 1 是真实 MagicBox Dialog，屏 2–6 变成另一套宽高/圆角/无遮罩的「假弹框」。

### 2.1 同系列弹框锁定（强制，批量出稿时）

适用：同一 `prototypes/output/<feature>/` 下多屏共享同一入口容器（如都是「发布确认」Dialog）。

| 必须锁定（从已确认屏抄） | 允许随线框变化 |
|--------------------------|----------------|
| 外壳：深色顶栏 + 侧栏 + 流程编辑背景 | Dialog **内部**业务区块（Diff 区、空态、禁用说明等） |
| Dialog 外框：宽度比例、圆角、阴影、标题栏（左标题 + 右 X） | 标题文案（如「发布确认」→「修改节点：xxx」） |
| **半透明遮罩**压暗背景的方式与浓度 | 底栏次要按钮文案（须仍在同一底栏条内） |
| 底栏条位置与主按钮形态（确认发布等） | 表单字段有无、清单内容、警告条 |

**生成时 `reference_image_paths` 顺序（同系列后续屏）**：

1. **已确认的同系列 Dialog 金标准**（如 `designs/01-*.png`）— 放第一位  
2. 现网外壳 / Dialog 截图（`00`/`90`/`01`/`94`）  
3. 本屏 `shots/*.png`（只作内容结构，**不作弹框外形**）

**Prompt 必写**：

- `Reuse the EXACT same Dialog chrome as the first reference image (confirmed screen). Same width ratio, same mask, same title bar, same footer bar.`
- `Only change the inner content for this screen's wireframe. Do NOT invent a new modal frame.`
- `FORBIDDEN: second nested dialog, different modal width, floating card without mask, redesigning the dialog shell.`

**自检**：把后续屏与已确认屏并排，若弹框外轮廓明显不一致 → 不合格，重出。

## 3. 场景互斥与操作流转（强制）

| 约束 | 说明 |
|------|------|
| 尊重现网互斥 | 现网互斥的面板不得同屏叠开（典型：**节点配置** 与 **全局变量侧滑** 互斥） |
| 跨屏不跳语境 | 多步向导应留在**同一入口语境**（如始终在节点配置 + Dialog 内步进）；禁止「下一步」突然关掉 A 面板再打开互斥的 B 面板 |
| 事后入口与创建向导解耦 | 「事后编辑 / 列表入口」可单独成屏，但不得伪装成创建向导的下一步 |
| 出稿前先画清流转 | README / Mermaid 写明：每屏入口、上一步从哪来、下一步去哪、取消回到哪；流转别扭时先改方案再出图 |

**反例**：屏 1 在节点配置 Dialog 点「下一步」→ 屏 2 变成「全局变量 > 编辑」侧滑且无节点配置。

**正例**：屏 1→2→3 均为「节点配置仍打开 + Dialog 步骤 1/2/3」；全局变量侧滑仅作事后微调。

## 4. 入口必须可感知（强制）

| 约束 | 说明 |
|------|------|
| 禁止无入口的「说明书页」 | 维护态 / 异常态 / 多场景拼贴屏，必须在图上或 README 标明**真实用户操作入口**（点哪个按钮/菜单/节点动作触发） |
| 入口写进标注或卡片标题 | 如「入口：画布删除分支节点」「入口：顶栏 → 全局变量侧滑」 |
| 非独立页要说清楚 | 若不是侧栏菜单页，禁止画成独立「健康检查中心」之类；应叠在现有画布/侧滑/Dialog 上 |

**反例**：一屏堆了三种异常卡片，却看不出从哪点进来。

---

## 5. 主路径 + 放弃/旁路路径（强制）

| 约束 | 说明 |
|------|------|
| 新能力默认路径要出稿 | 如「推荐聚合」主路径 |
| 不选新能力时也要出稿或写清 | 用户选「复用 / 取消 / 手动」等时：后续步骤如何置灰、主按钮如何变化、是否退回单步确定 |
| 禁用态可见 | 不可用的步骤条、按钮须**置灰禁用**，并有短文案说明（如「未选择聚合时，后续步骤不可用」） |
| 底栏随分支变化 | 进入多步时用「下一步」；不进入多步时用现网单步「确定」，勿同时放两个都可点的主按钮 |

**正例**：选「复用」→ 步骤 2/3 置灰，「下一步」禁用，底栏「取消 / 确定」。

---

## 6. 交互标注落点（强制）

| 约束 | 说明 |
|------|------|
| 文案与落点一致 | 写「弹窗内 / 实时校验 / 底栏」时，引线必须指到该区域 |
| 禁止悬空右栏 | 不得把全部 callout 堆在远离目标的右侧，箭头指空或指错 |
| 圆点贴目标 | 优先短引线；生成后目视：编号 ↔ README 元素列 ↔ 图上落点 |

详见 [reference.md](reference.md)「交互标注样式与落点」。

---

## 7. 文档与单据同步（方案变更时强制）

当评审改变**交互流转 / 入口 / 主旁路**（不仅是配色）时，须同步：

1. 原型 `README.md` + 相关 `screens/*.md`
2. 关联 spec（`docs/specs/` 或 `.knowledge-base/...`）
3. 若有 plan，更新对应步骤
4. 关联 TAPD：更新描述或留评论（方案一句话 + 路径链接）

仅改视觉标注落点、不改流转时，可只更新 `designs/`。

## 9. 出稿自检清单（每屏）

- [ ] 已按索引传入现网参考图；布局未自创整页结构
- [ ] Dialog 有遮罩；容器类型与现网一致；无伪造壳
- [ ] 未叠开现网互斥面板；多步向导未跨语境跳转
- [ ] 非主路径屏已标明入口；维护态不是无入口说明书页
- [ ] 主路径与「不选新能力」旁路均有说明或独立稿；禁用态置灰
- [ ] 标注引线落点正确
- [ ] 脱敏通过；README 已链到本屏 designs
- [ ] PNG 无 `caBX` 等私有块；GitHub 可预览
