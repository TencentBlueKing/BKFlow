### Tenant access constraints

When multi-tenancy is enabled, an all-tenant application must specify the request tenant through `X-Bk-Tenant-Id`. A single-tenant application may omit this header and use the authenticated application tenant in the JWT; any explicit header must match it. The request tenant must match the tenant of the resource's space. An all-tenant application must create separate spaces for each tenant. Existing application-to-space/template bindings still apply. If the JWT contains an authenticated user, that user's tenant must also match. Missing or mismatched tenant information causes the request to be rejected.

Application-authenticated endpoints do not require an additional user identity. SDK user-authenticated endpoints still require an authenticated user; platform administrators and space administrators cannot cross tenant boundaries. Disabling multi-tenancy preserves single-tenant behavior.

### Resource description

Import simplified workflow JSON and create a template. Two formats are supported:

- **v1 (array):** `a2flow` is a JSON array and requires a top-level `name`.
- **v2 (object):** `a2flow` is a JSON object with `name` inside it; recommended for AI agents.

The endpoint selects the converter automatically from the type of `a2flow` (array or object).

## v2 protocol (recommended)

Suitable for workflows generated by AI agents / LLMs, with fewer tokens and a simpler structure.

#### Endpoint parameters

| Field           | Type     | Required | Description                                |
|--------------|--------|----|-----------------------------------|
| a2flow       | object | Yes  | a2flow v2 JSON object (see structure below)         |
| creator      | string | No  | Created by                               |
| scope_type   | string | No  | Workflow scope type; supply both scope_type and scope_value or neither |
| scope_value  | string | No  | Workflow scope value; supply both scope_type and scope_value or neither   |
| auto_release | bool   | No  | Whether to publish automatically; default: false                  |

#### a2flow object structure

| Field        | Type     | Required | Description                          |
|-----------|--------|----|-----------------------------|
| version   | string | No  | Protocol version; default: `"2.0"`             |
| name      | string | Yes  | Workflow name                        |
| desc      | string | No  | Workflow description                        |
| nodes     | list   | Yes  | Node array (must not be empty)                  |
| variables | list   | No  | Global variable array                      |

#### Node structure (elements of nodes)

| Field                  | Type          | Required    | Description                                                      |
|---------------------|-------------|-------|---------------------------------------------------------|
| id                  | string      | Yes     | Unique node ID                                                 |
| name                | string      | No     | Node display name                                                  |
| type                | string      | No     | Node type; default: `"Activity"`; see allowed values below                              |
| code                | string      | Yes for Activity | Plugin code                                                 |
| data                | object      | No     | Plugin parameters as a flat `{"key": value}` object                             |
| next                | string/list | Yes except for EndEvent | Next node ID (string for Activity/ConvergeGateway; array for branch gateways)         |
| plugin_type         | string      | No     | Plugin type hint: `component` / `remote_plugin` / `uniform_api`    |
| conditions          | list        | Yes for ExclusiveGateway | Condition array `[{"evaluate": "expression"}]`, corresponding one-to-one with next              |
| default_next        | string      | No     | Default branch target ID for ExclusiveGateway                               |
| converge_gateway_id | string      | No     | Explicit converge gateway ID; inferred automatically if omitted                                     |
| stage_name          | string      | No     | Step name; defaults to name                                        |

#### Node types

| type                        | Description     | Type of next |
|-----------------------------|--------|---------|
| Activity (default)                | Activity node   | string  |
| StartEvent                  | Start event   | string  |
| EndEvent                    | End event   | None       |
| ParallelGateway             | Parallel gateway   | list    |
| ConditionalParallelGateway  | Conditional parallel gateway | list    |
| ExclusiveGateway            | Exclusive gateway   | list    |
| ConvergeGateway             | Converge gateway   | string  |

**Implicit insertion:** if nodes contains no StartEvent / EndEvent, the converter inserts them automatically.

#### Variable structure (elements of variables)

| Field          | Type     | Required | Description                                          |
|-------------|--------|----|---------------------------------------------|
| key         | string | Yes  | Variable reference key, in the form `${variable_name}`                           |
| name        | string | No  | Variable display name                                      |
| value       | any    | No  | Default value                                         |
| source_type | string | No  | `custom` (default) / `component_outputs` / `system` |
| custom_type | string | No  | `input` (default) / `textarea`                     |
| description | string | No  | Variable description                                        |
| show_type   | string | No  | `show` (default) / `hide`                          |

```json
{
    "bk_app_code": "xxxx",

            {"id": "n4", "name": "成功通知", "code": "bk_notify", "data": {"bk_notify_title": "成功"}, "next": "cg2"},

```

#### v2 error response format

The v2 protocol returns a structured error array for AI agents to parse and correct:

```json
{
    "result": false,
    "errors": [
        {
            "type": "INVALID_REFERENCE",
            "node_id": "n1",
            "field": "next",
            "value": "nonexistent",
            "message": "节点 'n1' 的 next 引用了未定义的节点 'nonexistent'",
            "hint": "可用的节点 ID: ['cg1', 'end', 'n1', 'n2', 'start']"
        }
    ],
    "code": 1
}
```

Error types:

| type                     | Description            |
|--------------------------|---------------|
| MISSING_REQUIRED_FIELD   | Missing required field        |
| INVALID_REFERENCE        | Reference to a nonexistent node     |
| DUPLICATE_NODE_ID        | Duplicate node ID      |
| CONDITIONS_MISMATCH      | The number of conditions does not match next |
| INVALID_DEFAULT_NEXT     | The default_next target is not in next |
| UNKNOWN_PLUGIN_CODE      | Plugin code not found    |
| AMBIGUOUS_PLUGIN_CODE    | Multiple registries match; specify plugin_type |
| CONVERGE_INFER_FAILED    | Unable to infer the converge gateway    |
| UNSUPPORTED_VERSION      | Unsupported protocol version      |
| RESERVED_ID_CONFLICT     | Reserved ID conflicts with the node type |

## v1 protocol (compatibility)

#### Endpoint parameters

| Field           | Type     | Required | Description                                |
|--------------|--------|----|-----------------------------------|
| name         | string | Yes  | Template name                              |
| a2flow       | list   | Yes  | Simplified workflow JSON array                      |
| creator      | string | No  | Created by                               |
| desc         | string | No  | Template description                              |
| scope_type   | string | No  | Workflow scope type; supply both scope_type and scope_value or neither |
| scope_value  | string | No  | Workflow scope value; supply both scope_type and scope_value or neither   |
| auto_release | bool   | No  | Whether to publish automatically; default: false                  |

---

The a2flow array supports the following 10 component types. Recommended order: workflow name, StartEvent, Activity/Gateway nodes, EndEvent, all Links, then all Variables.

#### Workflow name

Required to identify the workflow.

```json
{"type": "name", "value": "流程名称"}
```

---

#### StartEvent

Start node. Each workflow has exactly one, with the fixed ID `start`.

```json
{"type": "StartEvent", "id": "start", "name": "流程开始"}
```

---

#### EndEvent

End node. Each workflow has exactly one, with the fixed ID `end`.

```json
{"type": "EndEvent", "id": "end", "name": "流程结束"}
```

---

#### Activity

Activity node (plugin node).

```json
{"type": "Activity", "id": "n1", "name": "执行脚本", "code": "job_fast_execute_script", "data": {"script_content": "echo hello"}}
```

| Field       | Required | Description                                    |
|----------|----|---------------------------------------|
| id       | Yes  | `n1`, `n2`, `n3`, etc., in ascending order             |
| name     | Yes  | Node display name                                |
| code     | Yes  | Plugin code (such as `job_fast_execute_script`, `pause_node`, or `bk_notify`) |
| data     | No  | Flat key-value pairs `{"key": "value"}`; reference variables using `${variable_name}` and supply only needed parameters |
| stage_name | No | Step name; defaults to name                     |

---

#### ParallelGateway

Parallel gateway. All branches execute, and convergence waits for all of them. **Must** be paired with a ConvergeGateway.

```json
{"type": "ParallelGateway", "id": "pg1", "name": "并行分发"}
```

| Field                  | Required | Description                                |
|---------------------|----|-----------------------------------|
| id                  | Yes  | `pg1`, `pg2`, etc., in ascending order             |
| name                | Yes  | Gateway display name                            |
| converge_gateway_id | No  | Corresponding converge gateway ID; inferred automatically if omitted                 |

---

#### ConditionalParallelGateway

Conditional parallel gateway. All matching branches execute. **Must** be paired with a ConvergeGateway.

```json
{"type": "ConditionalParallelGateway", "id": "cpg1", "name": "条件并行", "conditions": [{"evaluate": "${env}=='prod'", "target": "n1"}, {"evaluate": "${env}=='test'", "target": "n2"}]}
```

| Field                  | Required | Description                                |
|---------------------|----|-----------------------------------|
| id                  | Yes  | In ascending order                              |
| name                | Yes  | Gateway display name                            |
| conditions          | No  | Condition array; each item contains `evaluate` (condition expression) and `target` (target node ID) |
| converge_gateway_id | No  | Corresponding converge gateway ID; inferred automatically if omitted                 |

---

#### ExclusiveGateway

Exclusive gateway. Exactly one matching branch executes; multiple matching conditions cause an error.

```json
{"type": "ExclusiveGateway", "id": "eg1", "name": "条件判断", "conditions": [{"evaluate": "${status}=='pass'", "target": "n2"}, {"evaluate": "${status}!='pass'", "target": "n3"}]}
```

| Field       | Required | Description                                    |
|----------|----|---------------------------------------|
| id       | Yes  | `eg1`, `eg2`, etc., in ascending order                 |
| name     | Yes  | Gateway display name                                |
| conditions | No | Condition array; each item contains `evaluate` (condition expression) and `target` (target node ID) |

- Conditions must cover every possible case.
- Set an `is_default` branch on a Link to handle unmatched cases.
- **Must** be paired with a ConvergeGateway.

---

#### ConvergeGateway

Converge gateway. Pairs with ParallelGateway / ExclusiveGateway / ConditionalParallelGateway.

```json
{"type": "ConvergeGateway", "id": "cg1", "name": "汇聚"}
```

| Field   | Required | Description                    |
|------|----|---------------------|
| id   | Yes  | `cg1`, `cg2`, etc., in ascending order |
| name | Yes  | Gateway display name              |

---

#### Link

Connection. All nodes must be connected through Links.

```json
{"type": "Link", "source": "start", "target": "n1"}
{"type": "Link", "source": "eg1", "target": "n3", "is_default": true}
```

| Field       | Required | Description                            |
|----------|----|-------------------------------|
| source   | Yes  | Source node ID                        |
| target   | Yes  | Target node ID                       |
| is_default | No | Set to `true` for an exclusive gateway's default branch, used when no condition matches |

---

#### Variable

Global variable definition. Omit when there are no variables.

```json
{"type": "Variable", "key": "${ip}", "name": "目标服务器IP", "value": "", "source_type": "custom", "custom_type": "input", "description": "执行脚本的目标服务器IP"}
```

| Field          | Required | Description                                          |
|-------------|----|---------------------------------------------|
| key         | Yes  | Variable reference key, in the form `${variable_name}`                           |
| name        | No  | Variable display name                                      |
| value       | No  | Default value (may be empty)                                    |
| source_type | No  | `custom` (custom variable, default) / `component_outputs` / `system` |
| custom_type | No  | `input` (single-line, default) / `textarea` (multiline); applies only when source_type is custom |
| description | No  | Variable description                                        |
| show_type   | No  | `show` (visible, default) / `hide` (hidden)                  |

---
