# PR #927 租户边界与单租户运行约定

## 业务契约

- 普通用户、空间管理员、平台管理员的当前身份租户都必须等于资源所属空间租户。管理员权限和资源 token 均不能越过这条边界。
- 当前只支持 `tenant_mode=single` 的空间。全租户应用在各租户创建独立空间，不支持全租户共享空间。
- 插件 code 全局唯一；系统租户插件允许所有租户访问。共享插件的授权修改保留插件负责人约束，租户管理员不能代管其他身份的插件。第三方 API 插件协议不引入用户身份。
- 开启多租户时缺少租户身份、归属不一致或任务缺少可恢复的租户信息均拒绝处理，不回退为 `system` 或旧单租户协议。

## 入口与身份

### Web 与 SDK 用户态

从登录用户身份读取租户；若同时有已认证的网关用户，JWT 用户租户必须一致。SDK 已认证应用的本次请求租户也必须一致。列表、详情、批量操作、模板/快照引用、任务代理和统计均按空间归属约束。

网关认证后端保留用户租户，但不复用其他租户或归属为空的历史管理员记录。存量用户需通过可信登录流程确认身份；不要未经核实批量赋予租户及管理员权限。多租户下关闭原生 Django admin 入口，使用租户内业务管理页面。Engine 模块路由的全局部署配置由部署维护流程管理。

### APIGW 应用态

只接受网关中间件认证后的应用身份，保留原有应用与空间/模板绑定：

| 应用类型 | 本次请求租户 |
| --- | --- |
| 单租户应用 | JWT 中的应用租户；可省略 `X-Bk-Tenant-Id`，传入时必须一致 |
| 全租户应用 | 必须用 `X-Bk-Tenant-Id` 选择租户，并匹配目标空间 |

全租户应用本身拥有选择不同租户的能力，请求头只用于选择资源范围，不能替代已认证应用或原有资源权限。若 JWT 同时包含已认证用户，用户租户也必须匹配。无用户态调用不额外要求用户登录。

创建空间的 `tenant_id` 必须等于本次请求租户；通过模板或任务 ID 调用的接口也检查真实所属空间。变量的创建、查询、更新、删除补齐应用与空间绑定。多租户下本地鉴权豁免不会跳过租户边界。

这一约定对应网关官方实现：[`bk-tenant-validate.lua`](https://github.com/TencentBlueKing/blueking-apigateway-apisix/blob/master/src/apisix/plugins/bk-tenant-validate.lua) 允许已认证全租户应用选择租户，限制单租户应用的请求头；[`bk-jwt.lua`](https://github.com/TencentBlueKing/blueking-apigateway-apisix/blob/master/src/apisix/plugins/bk-jwt.lua) 签发应用及用户身份。BKFlow 同时在后端复核身份与资源关系，发布前仍需使用实际部署的网关版本联调。

### 模块与异步执行

Engine 仅接受有效模块凭证，并按内部空间头约束任务、周期任务及引擎管理入口；不再依赖平台管理员透传标记。Interface 只有显式标记的内部接口可使用模块身份。Engine 不查询 Interface 数据库。

任务创建从已验证的空间归属写入租户；历史任务上下文继续从本 Engine 的任务记录恢复租户。存量空间、任务和周期配置的回填步骤见 [存量兼容方案](../plans/2026-09-15-pr927-compatibility.md)。

## 单租户运行与辅助配置

- 可以保持 `BKPAAS_MULTI_TENANT_MODE=false` 运行；旧环境也支持 `ENABLE_MULTI_TENANT_MODE=false`。两者都有值时前者优先，并在 blueapps 初始化前统一。
- 关闭多租户时，创建空间/任务可省略租户；空间创建/编辑的空租户字符串归一为 `default`。前端在此模式不主动附加租户字段。
- 保留旧通知渠道的 `label/is_active` 与新渠道的 `name/enabled` 兼容，以及旧审批单据协议。
- 用户时区缓存包含租户；开启多租户且缺少用户租户时不调用用户服务。插件请求缺少租户时在发出请求前拒绝。
- `BK_PLUGIN_SYNC_TENANTS` 会去除空项、首尾空格和重复项；未配置或全部为空时使用系统租户。
- `init_tenant --tenant_id` 必须显式传入租户；ITSM 系统创建或迁移返回业务失败/异常时以失败退出，不打印成功。该命令用于多租户部署。

关闭多租户开关不会将已经分属不同租户的数据重新合并，也不是多租户生产环境的回滚方案。保持单租户部署与多租户转单租户需分开处理。

## 验证边界

本地验证使用独立临时 MySQL、内存缓存/队列及模拟的外部服务，不执行真实租户初始化、生产回填、通知或审批写入。覆盖跨租户管理员访问、列表/统计、模板与快照、批量引用、应用态访问、Engine 空间约束、旧输入与服务协议、配置优先级、缓存隔离、初始化失败，以及前端渠道渲染和空间提交。

本轮最终回归：Interface 相关测试 1,156 项通过，Engine 任务视图、租户、配置与服务兼容测试 148 项通过；前端表单测试及生产构建通过（构建保留 73 条告警）。修改文件的 Black、Flake8、前端 ESLint 检查通过。Django 系统检查无错误，保留原有 `Label.label_scope` JSONField 默认值告警。102 个 APIGW operationId 无重复，92 份 Markdown 与文档压缩包逐字一致。

上线前仍需验证真实登录、网关 JWT/请求头、实际 SDK 版本、每个 Engine 的数据回填、旧在途任务和第三方插件执行/回调。本地单元测试、前端构建和 CI 不等于目标环境验收。
