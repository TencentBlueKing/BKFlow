## 1. 目标、范围和评审边界

让空间管理员用一套目录、审核、启停和推荐规则管理内置插件、蓝鲸插件及 V2/V3/V4 API 插件；让画布与现有网关使用相同的可选范围，同时保留存量节点的查看、编辑和执行能力。

本期包含：逐插件清单、两级目录、三种新插件策略、四类状态、有限重试和恢复、推荐与排序、当前引用及 CSV、AI 分类、同插件换版本和跨插件替换参数保留、存量迁移与旧接口兼容。

本期不包含：空间整体管理开关、隐藏状态、失效清理、来源分类绑定、管理员手工插件排序、历史引用查询、收藏、最近使用、独立审计页面、新的对外目录管理 API。现有网关插件列表过滤、流程更新校验和 API 文档同步仍在本期。

### 1.1 不重新讨论的已确认规则

| 范围 | 必须保留的规则 |
| --- | --- |
| 默认行为 | 所有空间默认具有插件管理；新空间保留原可用范围；新插件默认直接启用，按来源原有分类归类；存量空间通过独立命令手动初始化，默认 migrate 只处理表结构 |
| 状态 | 启用、待审核、未启用、已失效；首次来源超时或鉴权失败立即失效；来源恢复还原原管理决定，不重送审核 |
| 推荐 | 上限 10；主动停用取消推荐并释放名额；失效保留推荐且占名额；任何排序都先推荐组，两组分别排序；批量超限整批拒绝 |
| 保存 | 已有流程新增不可选插件节点需拦截，包括待审核；已有同插件节点不能为新节点放行；整流程新建、复制、导入及网关创建、回滚例外保留 |
| 存量访问 | 详情、表单、版本不得复用可选列表过滤；管理停用及仅同步超时/鉴权失效不阻止存量编辑、启动、调试；真实调用失败仍如实反馈 |
| 目录 | 两级、同级唯一、根目录末尾新增、子目录选择父目录后追加末尾；删除提升子目录，直接插件含未启用移入未分类 |
| AI | 只分类，不审核；人工无结果不变，失败报错；自动 AI 无分类结果进入未分类；撤销恢复完整编辑前状态，保存后撤销按钮消失 |
| 引用 | 当前发布与当前草稿按流程去重；节点按各自版本展示；草稿筛选仅草稿引用；无草稿、未发布、未引用分别表达 |
| 身份与参数 | 插件身份不含版本；旧 API 无法识别时独立提示；跨插件只保留同名参数，同插件换版本按同 key、同表单类型保留 |

## 2. 现状与方案取舍

### 2.1 已核实的代码事实

| 入口 | 当前行为 | 设计影响 |

| `bkflow/plugin/models.py` | `OpenPluginCatalogIndex` 保存来源快照；`SpaceOpenPluginAvailability` 保存 V4 enabled | 可复用来源能力；不能把仅 V4 的表直接当全类型管理模型 |

| `bkflow/plugin/space_plugin_config_parser.py` | `default` 与各 scope 可有不同 allow/deny 规则 | 不能把所有 scope 压成一个空间状态，也不能要求管理员清掉覆盖才迁移 |

| `bkflow/plugin/services/open_plugin_snapshot.py` | 建任务和启动校验会检查空间 enabled、目录有效性 | 移除管理停用阻断，拆分来源同步异常与真实来源不可用；保留精确版本、租户及授权检查 |
| `bkflow/template/models.py` | 草稿原地更新，发布将草稿变成正式快照 | 引用索引必须处理角色切换，不能只监听保存草稿 |
| `frontend/src/views/template/TemplateEdit/NodeConfig/NodeConfig.vue` | 同时承担列表衍生版本、详情加载、替换与换版本 | 详情/版本读取与列表解耦，参数保留提取成可测试函数 |
| `module_settings.py`、部署架构 | Interface 与 Engine 分开安装应用；only_calculation 可共享库，all_resource 切换独立库 | 新目录表只归 Interface；Engine 不直接查询目录 ORM |

### 2.2 Approaches：延续已明确的方向

| 方案 | 取舍 | 本稿处理 |
| --- | --- | --- |
| 独立 `bkflow.plugin_catalog`，来源适配＋空间清单＋独立管理设置 | 新模型与迁移成本较高；能统一全类型、失效记录、推荐、当前引用 | **沿用 V2 第七节及旧设计已明确方向**，细化本期契约 |
| 扩展现有 V4 表并在各来源查询中加逻辑 | 起步少建表，但 V2/V3、内置、蓝鲸容易形成不同状态与权限路径 | 不采用；保留现有查询和运行快照作为适配边界 |
| 每次请求实时聚合来源 | 少存数据；来源失败时难以保留清单，分页、失效和推荐一致性差 | 不采用；不满足本次已确认目标 |

这次是一个跨管理页、画布、网关、同步和迁移的项目级改动。下文先固定共用契约，随后按可验证能力拆分；不顺带重构引擎或所有流程写入口。

## 3. 部署归属与模块边界

Interface 内新增 `bkflow.plugin_catalog`，职责分为身份、来源采集、管理命令、可选列表、引用、保存校验、迁移、AI 结果校验。沿用 Django/DRF、MySQL、Celery 和 Vue 2，不新增服务进程或消息系统。

- **来源系统**继续负责平台准入、真实插件元信息、版本和执行；目录服务不复制完整表单作为另一个真源。
- **Interface web**提供管理接口、画布查询、当前引用和共用保存校验；**Interface worker/beat**执行采集、重试和初始化工作。
- **Interface 数据库**保存目录、决定、快照和引用；缓存只加速，不决定状态。
- **Engine**继续使用现有任务快照及 Interface 内部接口，不安装目录应用、不创建目录表、不跨库查管理状态。
- **前端**消费后端的 `effective_state`、`allowed_actions` 和错误项，不另算一套状态流转。

## 4. 数据模型建议

以下名称是拟定的新模型。所有查询先绑定经鉴权的空间；关联对象必须属于相同空间。空间所属租户取既有 Space，不从客户端接受另一份租户值。

| 模型 | 主要字段 | 约束 |
| --- | --- | --- |
| `SpaceCatalogConfig` | `space_id`、`policy`、`policy_revision`、来源条件组、AI 范围、`revision`、`initialization_status` | 空间唯一；初始化进度不是产品开关；无 enabled/hidden 字段 |
| `PluginInventory` | 空间、`plugin_key`、类型、`source_key`、来源插件 ID、name/code、描述、来源分类、最新版本发布时间、来源有效性/原因、发现时间、最后成功观测代次 | 唯一 `(space_id, plugin_key)`；保留失效记录；不存调用凭证或完整执行参数 |
| `SpacePluginSetting` | inventory 关联、`management_state`、`ever_enabled`、当前目录、审核目标目录、`recommended`、停用原因/替换对象、修改人时间、归类方式 | 管理状态仅 enabled/pending/disabled；invalid 由来源状态合成；推荐独立保存；无插件排序序号 |
| `PluginDirectory` | 空间、父目录、名称、兄弟顺序、系统标记 | 两级；根层也必须落实同名唯一，不能只依赖 nullable parent 的数据库唯一约束；系统未分类不可删改移 |
| `TemplatePluginReference` | 空间、流程、内容角色、snapshot ID、内容摘要、插件身份、节点路径/名称/插件版本 | 当前角色为 published/draft/current；同版本不同节点不按名字合并；不展开引用的其他流程 |
| `UnresolvedApiReference` | 流程、内容角色、snapshot、节点路径、诊断原因 | 无假造 plugin_key；独立查询，不混入插件或引用数量 |
| `CatalogInitialization` | 空间、批次、旧配置快照、校验摘要、进度/错误 | 幂等；失败不留下部分管理数据；快照是恢复资料，不是关闭功能入口 |
| `SourceSyncState` | 空间、来源/请求范围、代次、attempt、last_error、next_run、terminal | 记录有限重试；旧任务不能覆盖新成功结果；锁和任务消息均不是唯一真源 |
| `CatalogChangeRecord` | 空间、对象、操作人、前后值、归类来源、关联请求/AI 结果 | 供排查，不增加独立审计页面；敏感参数不入记录 |

不为普通空间引入 `LegacyScopeVisibility` 表或新的 scope 配置界面。初始化预览检测实际存在的旧限制，少量例外走模块内 `services/legacy_scope.py`，复用已有解析器并保留旧配置快照；不能将其静默合并为空间级 enabled。例外空间的配置差异单独核对，不阻塞无此配置空间的初始化，也不自动清理旧限制。

统一身份沿用需求：`builtin:{code}`、`bk_plugin:{plugin_code}`、`uniform_api:{source_key}:{api_id}`。版本、目录、节点 ID 不参与身份。API 缺少稳定 ID 或 source_key 无法可靠还原时，不用 URL 哈希代替真实身份。

“原目录”使用当前保留的目录归属；删除目录必须同步修改未启用插件归属和待审核目标目录，避免启用时回填失效目录。归类方式建议枚举 `source_category/manual/ai/policy/uncategorized`，另存原因区分目录删除、AI 无结果等，不把原因当成新状态。

## 5. 状态、推荐与查询

### 5.1 两个维度合成四个状态

`effective_state = invalid if source_invalid else management_state`。

| 事件 | 管理决定 | 来源状态 | 推荐 |
| --- | --- | --- | --- |
| 首次发现 | 按当时策略生成一次；默认 enabled | 记录观测结果 | 默认不自动推荐 |
| 审核启用/不启用 | enabled / disabled，启用时置 ever_enabled | 不改 | 不自动推荐 |
| 主动停用 | disabled，保留曾启用标记、原因及建议 | 不改 | 清除并释放名额 |
| 来源超时、鉴权失败、确认删除 | 不改 | invalid，保存真实原因 | 不改且继续占名额 |
| 新成功证据 | 不改，不重新跑策略 | 更新对应范围有效性 | 不改 |
| 策略切换 | 既有记录不改 | 不改 | 不改 |

管理读接口返回合成状态、原管理决定、来源原因、适用操作。只有曾启用后停用的插件提供停用配置；失效列表无清理操作。来源恢复与管理员动作并发时，来源同步只更新 inventory，不能用旧快照覆盖 setting。

### 5.2 推荐并发与排序

推荐命令在同一空间配置行锁内读取占用数并提交。占用数包含失效推荐项，已推荐项重复提交不重复占位；待新增数超过剩余名额整批拒绝，返回剩余名额。状态在确认前变化时重新验证，不采用前端计数。

可选列表先经过平台准入、空间/租户及兼容 scope 限制，再要求管理 enabled 且来源有效；分页必须在过滤、排序之后。详情/表单/版本走独立服务，不套可选条件。

排序始终 `recommended DESC`，再按所选字段/方向。名称使用统一的拼音排序键，发布时间使用真实最新版本发布时间，引用数使用当前流程去重数。实现采用同值最后以稳定 `plugin_key` 升序；没有真实发布时间时保留 null、不拿发现时间冒充，空值置后。默认“推荐序”的组内次序使用名称拼音升序，不增加管理员排序控件；具体共用函数与依赖见实现计划 T8。

## 6. 来源适配、失效与有限重试

### 6.1 统一采集契约

`Provider.collect(SourceContext) -> SourceObservation`，其中包括：本次请求覆盖范围、条目、完整性、分页完成证据、请求代次、成功/失败类别。来源适配保留实际 `source_key`，遍历所有已配置来源，而不是只读 default。

- 内置：从组件注册信息/允许列表取得稳定 code，版本仅为属性。
- 蓝鲸：复用本地插件同步与空间授权，不把本空间无权访问等同来源删除。
- V2/V3/V4 API：都读取逐个 API 条目；保留 wrapper version 与业务 version 的区别；按来源协议取完分页，不复用“limit=200 的第一页”作为完整快照。
- remote/cache_only/hybrid 是采集适配配置，不是绕开统一管理的理由；V2/V3 不能继续只为整个来源创建一个条目。
- 只有完整、成功且范围明确的清单才能以“未出现”判定删除。分页中断保留旧条目，不把未取到的条目写成删除；若中断原因是超时/鉴权，仍按已确认规则将请求覆盖范围标为该原因失效。
- 首次失败也保存来源级错误，避免“没获取到任何插件”被展示成已确认的零条成功。

来源分类只用于首次归类：保留来源分类 code/名称作为快照，与空间目录建立一次性对应，不建立自动跟随。技术建议先按来源原有平面分类创建根目录；相同名称复用同名根目录，无来源分类进入未分类。多级、重名、超长或不可映射分类在预览中报告，不自动裁剪名称或改变层级；接入适配必须给出确定映射后才能完成该来源的迁移。

### 6.2 错误映射与重试实现

| 观测 | 状态处理 | 重试处理 |
| --- | --- | --- |
| 超时/连接类暂时失败 | 首次按实际覆盖范围失效，原因 timeout/transport | 有限指数退避 |
| 401/403 或明确鉴权失败 | 首次失效，保留管理决定/推荐 | 不用同一无效凭证连续重试；配置/凭证变更触发新检查 |
| 确认删除 | 标记 source_deleted，保留记录 | 不对同一删除结论进行短周期重试 |
| 限流/临时服务异常 | 保存真实错误；是否属于失效要由协议映射明确，不冒称删除 | 对来源声明的可重试错误应用有限退避 |
| 无法解析/分页不完整 | 不宣告删除，不提交半套来源快照 | 记录具体错误，协议问题不盲目重试 |

技术默认参数：首次请求之外最多重试 3 次，基础等待 10 秒、按 2 倍增加为 10/20/40 秒，可增加不超过 20% 抖动；同一轮最长 5 分钟，次数或时限任一到达即结束。参数可配置，并记录实际终止原因；自动恢复只能来自新成功证据。

**已确认边界**：快速重试用尽后保留低频来源巡检，用于发现来源恢复；同一持续故障中的巡检失败不重新开启快速重试。实现沿用现有正常采集周期，不新增空间管理员配置。来源成功后结束本次故障；后续新故障可开始新的有限重试。凭证/配置变更产生新配置代次，可触发新检查。不能把无限重开重试轮次伪装成有限重试。

### 6.3 提交顺序

网络请求在事务外；提交时校验来源配置摘要和同步代次，过期结果丢弃。同一来源重复任务幂等；锁用来节流，数据库条件更新防止锁过期后的旧结果倒灌。来源元信息同步只写来源信息与首次发现记录，不覆盖已有目录、审核、推荐、停用配置。新插件策略使用发现记录携带的 policy_revision，避免重复任务按新策略重新审核存量。策略触发的 AI 分类是独立目录命令；“完全自由”模式允许按第 7 节修改范围内的存量目录，不与元信息同步不覆盖设置混淆。

普通新同步只处理已 ready 空间，未初始化空间不偷偷运行新插件策略。现有 V4 来源索引在运行快照/缓存消费者切换前保留元信息投影及精确版本；它不再独立决定空间 enabled。同步超时与真实来源版本失效按新原因区分，不能让旧索引的一位 unavailable 再次阻断允许的存量运行。

## 7. 目录编辑、审核和 AI

目录批量页在前端保存独立编辑副本；手工与 AI 修改进入同一编辑状态，带目录 revision 一次提交。后端在事务中验证两级、同级唯一、对象归属、系统目录限制、删除效果和排序，再统一保存。并发变化返回冲突，不静默覆盖他人改动。

删除预览与保存使用同一转换函数：提升被删目录的子目录；直接插件和目标目录引用移入未分类；子目录内插件保持。删除后提升产生重名等结构冲突时，返回明确冲突项由用户修改后再保存，不自动合并或重命名。多选祖先/子目录时先构造最终目标树，禁止依赖操作遍历顺序产生不同结果。

审核命令与分类结果分开：`enable(items)`、`decline(items)` 只根据显式管理操作改变管理决定。第 6 项的提交时机、第 7 项的批量确认界面保持暂定；后端接受逐项目录的数据结构可先设计，但不能以此认定前端交互已经定案。

AI 调用与结果提交分开：`classify(edit_state, selected_items, scope, prompt)` 返回分类变更建议或明确空结果；服务端校验合法插件、目录、两级限制与当前请求范围。AI 返回状态、推荐或审核字段应拒绝，不让模型改变管理决定。

- 人工模式有结果自动应用到当前副本；保存前保存完整 before 状态用于撤销；无结果保持字节等价状态，失败显示错误。
- 保存成功后清除本次撤销快照；旧请求晚到时不能覆盖已保存的新状态，使用请求序号和编辑 revision 丢弃过期结果。
- 自动策略先形成准入决定；AI 只决定目录，无结果进未分类；AI 失败与空结果分开记录，不由 AI 失败改变审核结果。
- 自动 AI 的“仅对增量分类”只允许修改本次新增插件归属，不能修改已有目录结构或存量插件；“完全自由”按已选择范围向 AI 提供存量目录和插件，并允许独立目录命令提交合法的结构/归属变更，包含覆盖范围内手工归类。两种模式都不修改审核、推荐、停用配置；策略切换本身不触发存量重处理。自由模式在新插件发现触发分类时生效，按 policy_revision 和目录 revision 检查过期结果，并记录每项归类来源。
- 每次实际归类记录 method、reason、actor、时间、策略/AI 请求关联；不记录来源凭证、流程参数或完整敏感提示内容。
- AI 接入由用户于本轮明确：预计使用 bkaidev LLM 接口，走 BKFlow 自己的应用凭证。接口与证据边界见下节，不再将供应商列为待选择。

### 7.1 bkaidev LLM 接入

已于 2026-10-30 在网关 `prod` 文档页核对：

| 接口 | 地址 | 已核实的鉴权要求 |
| --- | --- | --- |
| [aidev_llm_gateway_chat_completion](https://bkapigw.woa.com/docs/api-docs/gateway/bkaidev?apiName=aidev_llm_gateway_chat_completion) | `POST https://bkaidev.apigw.o.woa.com/prod/openapi/aidev/gateway/llm/v1/chat/completions` | 应用认证是；网关资源应用权限检查否；用户认证否；文档声明遵循 OpenAI Chat Completion 协议 |
| [aidev_llm_gateway_models](https://bkapigw.woa.com/docs/api-docs/gateway/bkaidev?apiName=aidev_llm_gateway_models) | `GET https://bkaidev.apigw.o.woa.com/prod/openapi/aidev/gateway/llm/v1/models` | 同上，返回当前可用模型；具体模型可见性仍须用 BKFlow 应用验证 |

公共头为 `X-Bkapi-Authorization`，值是含 `bk_app_code`、`bk_app_secret` 的 JSON 字符串。应用凭证从服务端 `settings.APP_CODE`、`settings.SECRET_KEY` 读取，与仓库现有应用客户端默认凭证来源一致；不让空间管理员填写另一份凭证，不向前端返回密钥，不从用户浏览器提取凭证。

新增模块内 `clients/bkaidev_llm.py` 负责应用态请求；不直接套用会把认证字段混入业务 body 的 `BKComponentClient._pre_process_data`。复用现有 HTTP 依赖即可；显式启用证书校验和请求超时，认证头不得进入日志。网关地址/环境及模型名由部署配置提供，不把文档中的 prod 写死为所有环境的唯一地址，也不自动选择第一款模型。

技术提案使用非流式请求，基础 body 为 `model`、`messages`、`stream=false`。分类消息只提供必要插件摘要、目录结构、选定范围与用户分类要求；模型输出按受约束 JSON 解析，再执行目录业务校验。暂不假定该接口一定支持 `response_format/json_schema`、工具调用或特定模型参数。

**证据边界**：网关文档未展开请求体字段、正常返回和错误体 schema，仅声明协议。上述基础 body 属于按声明协议拟定的客户端契约，实施前用测试替身及获准联调样本核验 `choices/message/content`、空结果、截断、拒绝、HTTP/协议错误和非 JSON 返回。当前未读取应用密钥，未发起真实 LLM 请求，未验证模型授权、额度或响应速度。源目录重试与 AI 请求失败是两条路径，不能把 AI 失败标成插件来源失效。

## 8. 当前引用和新增节点校验

### 8.1 两套目的，共用身份解析

`collect_direct_plugin_nodes(tree)` 输出插件身份、完整节点路径、名称与插件版本；遍历本流程拥有的内嵌画布/循环，遇到引用另一个流程的节点不展开其内容。身份无法识别的旧 API 单列诊断。

引用服务维护当前发布、当前草稿、未启用版本管理时唯一 current 三种角色。角色存在性从 Template/TemplateSnapshot 读取，不能用“查不到插件引用”推断“没有草稿”。同一流程命中任意当前角色计一次；仅草稿为 draft 命中且 published 不命中。

流程保存、发布、回滚、删除、新建、复制、导入的最终落库事务同步替换受影响的引用角色；只更新当前角色投影，不删除历史快照。统计与缓存使用引用 revision；回填未完成返回 not_ready，不返回 0。CSV 复用搜索与筛选查询但不带分页限制，并保留每个节点所属角色/快照及定位入口。

停用提示中的节点数量不要从跨版本相加得到：数据契约返回 published/draft/current 各自计数；若页面要求单一节点数，使用明确命名的版本计数或版本并列，不能偷偷复用流程数。联系信息仍保留 T13 建议状态。

### 8.2 保存校验建议

`validate_plugin_node_additions(baselines, incoming_tree, catalog_context) -> violations`：

1. 在服务器执行任何 ID 替换前读取原始提交树；基线来自服务端当前草稿和当前发布内容，不能由客户端提交。
2. 用 `(完整节点路径, plugin_key)` 做现有节点匹配，不以名称、数量或仅插件集合匹配。同插件切换版本不算新增；同 ID 改成另一插件，需要检查目标插件。
3. 当前请求中的新节点，即使与旧节点使用同一插件，仍单独检查 enabled/valid；待审核、未启用以及按规则失效的插件返回逐节点违规项。
4. 通过校验后才执行原有后端 ID 重建，引用索引用最终保存的节点路径。后端已知的 ID 映射只用于定位回写，不把所有节点重建误判成新增。
5. 整流程新建/复制/导入及网关创建/回滚使用显式操作上下文跳过“新增使用限制”；仍执行租户、平台授权、结构与其他既有检查，并更新引用索引。
6. 不将可选列表过滤用于存量详情或执行。拆开现有 `OpenPluginSnapshotService` 中的空间停用检查与真实来源/版本检查，避免其在建任务、启动、调试再次挡住已允许的存量节点。

服务端 ID 重建可在现有代码内解决；若第三方调用者提交前已自行重建全部节点 ID，服务端仅凭两份任意编辑树不能证明节点沿袭。实现前需要用 SDK/实际请求样本验证；确有该类客户时，需单独设计可信节点沿袭契约，不能退回插件数量差或客户端任意声明“这是旧节点”。这项是证据依赖，不改变需求的拦截规则。

保存检查与持久化之间需防止并发停用穿透。技术建议相关管理命令与流程更新按统一顺序锁空间目录配置及流程记录，事务内复查有效状态；网络表单读取在事务外。避免为了目录改造重构无关流程逻辑。

## 9. 接口契约草案

管理接口暂定挂在 `/api/plugin_catalog/`，仅平台管理员或当前空间管理员；使用侧复用现有权限组合，先校验租户/空间再执行权限 OR。分页、统计、CSV、批量对象和替换对象都执行同样的范围校验。

| 能力 | 请求/返回重点 | 边界 |
| --- | --- | --- |
| 管理列表/统计 | 状态、目录、类型、来源、组合搜索；返回 effective_state、allowed_actions、recommendation、directory、current_reference_count | 全部/目录数量包含失效；unknown API 独立 |
| 使用侧列表 | 名称/code、目录/类型、排序字段/方向、分页 | 仅 enabled＋valid；推荐先分组；所有来源过滤后分页；不泄露不可选项 |
| 状态批量读 | 插件身份数组；返回合成状态、真实原因、停用原因、替换建议 | 存量画布使用；不是可选列表 |
| 目录读取/提交/删除预览 | revision、目录变更、插件归属变更；返回新 revision 或冲突项 | 批量页整体提交；无来源绑定；第 6 项即时入口另列暂定 |
| 策略读取/保存 | 三种策略、互斥来源条件组、分类方式、AI 范围、policy_revision | 保存后只处理后续发现插件 |
| 插件启用/审核不启用/停用/配置 | 逐项身份与目标目录、原因、替换对象 | 第 7 项批量确认暂定；原因最多 200 字；从未启用无停用配置 |
| 单项/批量推荐 | 身份列表、expected_revision；返回占用、剩余名额或整批超限错误 | 10 个包括失效项；主动停用清除；无手工顺序接口 |
| AI 分类 | 当前编辑状态、选中范围、指令、request_revision；返回 patch/empty/error | 不执行审核；不直接提交人工批量页；已保存撤销清理 |
| 引用详情/CSV | flow query、published/draft_only/all、分页；角色存在性、version、node paths、readiness | 草稿仅草稿引用；CSV 全匹配；T13 联系字段仍建议 |
| 旧 API 诊断 | flow/snapshot/node path、无法识别原因 | 独立清单；不伪造 identity |
| 流程更新 | 共用新增校验返回 violations：plugin_key、node_path、实际原因、替换建议 | 画布与 APIGW 相同语义；不改变创建/回滚例外 |
| 旧 V4 三接口 | 代理新管理服务并标记废弃，保持旧调用协议适配 | 不能绕过新状态；旧表不再另做管理真源 |
| 旧空间配置写入 | `create_space/renew_space_config` 对旧插件配置给明确迁移错误 | 旧配置只读；无关闭管理后恢复写入 |

管理变更的 409 冲突及 `RECOMMENDATION_LIMIT_EXCEEDED`、`PLUGIN_NODE_ADDITION_FORBIDDEN`、`REFERENCE_NOT_READY` 等为拟定错误名，需与项目错误码注册方式统一。错误载荷不暴露无权访问的插件或其他租户资源。

## 10. 初始化、迁移和发布

迁移目标是所有空间默认具备能力，不能把内部 readiness 包装成用户开关，也不能把旧方案的“scope 有差异就要求管理员清理”沿用到本期。

已确认采用独立命令：默认 `migrate` 只建表和约束，不创建存量初始化任务、不采集来源、不回填目录或引用。拟定命令 `initialize_plugin_catalog`，显式选择 `--space-id` 或 `--all-spaces`，支持 `--dry-run`；命令同步处理所选空间并给出逐空间结果，失败可重复执行。不存在的空间参数报错；单空间失败不影响其他空间，任一失败最终返回非零状态。命令是运维初始化入口，不是空间功能开关。

外部来源访问在数据库事务外；每空间在所有必要快照与配置校验完成后原子切换为 ready。重复执行跳过已完成空间，不重置管理员决定；失败重跑从未完成空间继续。来源不完整或身份/分类无法可靠映射时输出原因，不以半套清单完成初始化。新空间仍自动初始化，不要求管理员执行该命令。

初始化服务复用于存量迁移和新空间创建：

1. 读取旧 `space_plugin_config`、V4 enabled、平台准入；获取完整来源快照。普通空间直接生成对比预览；检测到真实 scope 限制的例外空间单独列出，走兼容核对路径。
2. 旧空间当前可选项转为 enabled，当前不可选项保留原限制；V4 enabled=false 转未启用并保留其停用语义，不重新送审。
3. 按来源原分类建立目录，保存可追查的分类方式；不恢复来源绑定或旧隐藏状态。
4. 保存旧配置快照，回填当前引用与旧 API 诊断；每个空间事务失败整体回滚，不留下部分管理设置。scope 例外配置独立保留，不建立全量逐插件 scope 投影。
5. 校验初始化前后可选集合相等、V4 关闭记录保留、引用就绪后才标 ready；例外空间额外按原 scope 对比。失败空间明确记录未就绪，不伪造成功或零引用。
6. 新空间使用同一初始化服务，默认策略为直接启用＋来源分类；既有已发现插件不因重跑初始化而重置管理员决定。
7. 迁移后旧配置只读，旧网关写入明确失败。旧 V4 管理接口转发新服务，避免双写两个管理真源。

上线顺序建议：默认 migrate 建表 → 独立命令预览 → 手动执行初始化并核对结果 → 管理页与画布/网关同时接入 → 存量运行回归。初始化未完成的存量空间继续原读取路径，不把空目录解释为无可用插件；管理写入及引用新功能返回未就绪。此兼容仅服务发布过渡，没有用户开关，不能绕过已 ready 空间的新规则。技术发布可先试点，但不是新增空间开关。回退需要同版本数据快照与部署配套；已有新管理决策不能自动覆盖回旧快照而静默丢失，发布回退方案须单独列出核对步骤。
