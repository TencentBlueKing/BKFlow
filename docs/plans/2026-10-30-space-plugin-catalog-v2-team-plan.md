## 一、最终要交付的结果

管理员能在空间内统一管理内置插件、蓝鲸插件和 V2/V3/V4 API 插件；编排者在两套画布中看到一致的目录、可选插件和排序；网关列表与流程保存采用相同的空间规则。

开发与测试始终保留以下边界：

- 所有空间默认具有插件管理。默认新插件直接启用，按来源原分类归类；不增加整体开关或隐藏状态。
- 来源是否有效与管理员的启停决定分开保存。来源故障显示“已失效”，原管理决定和推荐保留；恢复后沿用原决定。
- 每空间最多推荐 10 个，失效推荐项仍占名额。主动停用清除推荐；推荐组始终在前，两组分别按用户选择的方式排序。
- 已有节点继续保留查看、编辑、建任务、启动和调试能力；在已有流程中新增不可选插件节点，要拦截保存。真实来源、版本和权限错误仍按实际情况报错。
- 引用只统计当前发布版本和当前草稿，并按流程去重。历史版本不混入当前引用；没有草稿与草稿未引用分别表达。
- AI 只帮助分类。人工 AI 无结果不改变内容，失败报错；自动策略无分类结果进入未分类，不由 AI 决定审核或启用。
- 存量空间用独立命令手动初始化，新空间自动初始化；默认 `migrate` 只建表，不采集来源、不回填业务数据、不派发初始化任务。

## 二、按什么顺序推进

整体按四批评审和联调。管理页、两套画布、网关和保存检查共享规则，功能交付前需要一起接通。

| 批次 | 对应任务 | 本批要形成的能力 | 主要协作方向 |
| --- | --- | --- | --- |
| 第一批：基础数据与来源同步 | 1—5 | 统一插件身份，保存目录与管理决定，完整采集来源并处理故障恢复 | 后端为主，测试核对状态和并发场景 |
| 第二批：引用、初始化与接口 | 6—10 | 算清当前引用，初始化存量空间，统一可选范围和保存检查，提供管理接口 | 后端、测试共同核对旧入口兼容 |
| 第三批：AI 与前端体验 | 11—15 | 接入 AI 分类、目录编辑、策略启停、引用定位和两套画布 | 前后端联调，产品核对交互与暂定项 |
| 第四批：完整验收与发布准备 | 16 | 跑通完整业务链路，形成初始化、回退和验收记录 | 开发、测试、发布人员共同完成 |

各任务的编号用于追踪依赖，不代表所有工作都必须逐项串行：任务 2、4、6 都以任务 1 为基础；任务 5 需要任务 2—4；任务 7 需要任务 2、4、6。前端可以依据已经明确的接口先准备模拟数据，真实接通仍要满足下面列出的依赖。

## 三、16 项任务与完成标准

### 第一批：让插件、目录和状态有统一依据

| 任务 | 要做什么、交付什么 | 怎样确认完成 |
| --- | --- | --- |
| 1. 统一插件身份和数据模型 | 建立插件清单、空间管理设置、目录、引用及同步记录。插件版本变化不改变身份；不同来源的 API 不会因名称或编号相同而合并。新表放在 Interface。 | 同插件不同版本识别一致；跨来源同编号仍是两个对象；失效不改管理决定；目录重名被拒绝；Engine 不直接使用新表。 |
| 2. 目录保存、移动和删除 | 实现两级目录、新目录追加末尾、多选子目录或插件移动、整页保存和删除预览。删除目录后提升子目录，直接插件及相关审核目标移入未分类。 | 预览与实际保存结果一致；子目录内插件保持归属；未启用插件也正确迁移；重名或并发冲突不产生半套修改；系统未分类目录受保护。 |
| 3. 新插件策略、审核启停和推荐 | 实现默认直接启用、全部审核、条件自动启用三种策略；提供启用、审核不启用、停用和推荐操作；保存停用原因及替换建议。 | 改策略不重审存量；推荐包含失效项且总数不超过 10；批量超限整批拒绝；两个管理员同时操作最后一个名额时仍正确；重新启用沿用保留目录。 |
| 4. 完整采集所有插件来源 | 覆盖内置、蓝鲸、V2/V3/V4 API 的全部配置和分页，保留身份、版本及来源分类；无法可靠识别的老 API 单列。 | 用超过 200 条、非默认来源、多配置指向同一来源等样本核对清单；某页失败时明确标记不完整；不把未取到的数据误判为删除，也不伪造插件身份。 |
| 5. 来源同步、重试和恢复 | 接入后台同步；首次超时或鉴权失败按实际影响范围显示失效；按原因决定是否重试；保留恢复检查和来源版本信息。 | 快速重试有次数和总时限，同一持续故障不会无限重开；旧失败结果晚到不能覆盖新成功结果；恢复保留原启停决定及推荐；来源同步不覆盖人工设置。 |

依赖：任务 2、4 基于任务 1；任务 3 基于任务 1、2；任务 5 基于任务 2、3、4。任务 5 产生的自动分类请求由任务 11 接入。

重试沿用原 plan 的技术默认值：首次请求外最多 3 次，等待 10/20/40 秒，可增加不超过 20% 的抖动，一轮最长 5 分钟。快速重试结束后只保留低频正常检查；无效凭证、确认删除和协议错误不盲目重试。恢复必须有新的成功证据。

### 第二批：接通现有流程、空间和网关

| 任务 | 要做什么、交付什么 | 怎样确认完成 |
| --- | --- | --- |
| 6. 当前引用及更新机制 | 建立当前发布版本、草稿和节点的对应记录；保存、发布、回滚、删除、新建、复制、导入时同步更新；提供查询和 CSV 导出。 | 6 个发布引用加 2 个仅草稿引用，得到 8 个去重流程；同名节点分别计数；只在历史版本引用的不计入；没有草稿与未引用区分；CSV 覆盖筛选后的全部结果。 |
| 7. 存量手动初始化、新空间自动初始化 | 提供独立初始化命令，支持预览、指定空间、全部空间和失败重跑；保留旧配置快照，初始化来源分类、管理状态和当前引用。少量旧范围限制单独兼容。 | 默认 migrate 没有业务初始化副作用；预览不写业务数据；一个空间失败不影响已成功空间；重跑不覆盖人工设置；旧 V4 明确关闭项保持未启用；新空间自动完成初始化。 |

| 10. 管理接口和旧入口兼容 | 提供目录、策略、启停、推荐、引用、CSV 及老 API 诊断接口；旧 V4 管理入口委托新服务；完成初始化后拒绝继续写旧空间插件配置。 | 普通用户、跨租户和跨空间请求按权限拒绝；批量对象逐个校验范围；首次采集失败不冒充零插件；管理搜索、筛选计数、引用概览和 CSV 各自口径一致；旧接口返回格式保持兼容。 |

AI 的服务和凭证方向已确认，实际环境、模型权限、返回样本及延迟仍需联调。AI 未配置时只在 AI 入口提示配置错误，基础插件管理和默认来源分类继续可用。

### 第四批：完成整体联调和发布准备

**任务 16：完整业务验收与运维交付。** 在任务 1—15 接通后，补齐集成遗漏，完成受影响的后端、Engine 和前端检查，形成初始化、故障处理和部署回退说明。真实 bkaidev 联调与目标环境业务验收分别记录结果。

至少用同一插件走通下列业务链路：

1. 新插件按策略进入待审核，管理员启用并推荐。
2. 来源首次超时后显示已失效，推荐继续保留并占名额。
3. 有限快速重试结束，后续低频检查成功，插件恢复原启用和推荐。
4. 管理员主动停用，推荐取消并释放名额；已有节点仍可编辑和运行，新加节点保存被拦截。
5. 删除所在目录，插件移入未分类；重新启用时回填未分类。

每一步都同时核对管理状态、来源有效性、目录、推荐、可选列表和当前引用。另行覆盖跨租户批量请求、两套画布、参数保留及准确版本跳转。

## 四、前后端和测试怎样交接

| 交接点 | 前一个环节提供什么 | 后一个环节据此做什么 |
| --- | --- | --- |
| 身份与状态，任务 1 → 后续任务 | 统一插件身份、管理决定、来源有效性和错误原因 | 各入口引用同一插件，按相同规则展示和检查 |
| 目录与管理，任务 2、3、10 → 任务 12、13 | 完整目录、插件归属、审核目标、推荐名额、允许操作及冲突结果 | 页面编辑后提交；遇到并发修改提示冲突，不静默覆盖 |
| 来源同步，任务 4、5 → 任务 7、8、11 | 完整性明确的来源清单、有效性、精确版本、分类请求 | 正确初始化、筛选和分类，区分失败与真实空结果 |
| 当前引用，任务 6、10 → 任务 14 | 去重概览、各版本节点、角色是否存在和具体目标版本 | 显示准确数字，跳到正确内容，按当前筛选导出全部结果 |
| 保存检查，任务 9 → 任务 15 | 被拒绝的具体节点、原因及可用替换建议 | 在画布上定位问题并提示用户处理 |
| AI 分类，任务 11 → 任务 12、13 | 明确的分类结果、空结果或错误，以及请求对应的编辑状态 | 应用合法结果、提示失败、支持撤销，丢弃已经过期的结果 |

详细字段、接口签名、代码文件和测试命令保留在原始 plan；本页用于团队理解任务与交接结果。修订号等内部字段用于判断并发修改，不作为界面上的业务版本展示。

## 五、验证怎么做，怎样记录完成

每项任务先用关键场景确认当前实现缺失，再实现并运行相关检查；测试连接错误需要先处理环境，不能当作业务失败用例通过。目录、推荐、初始化等并发行为使用独立 MySQL 测试库核验；插件来源、AI 和后台任务调度先用模拟服务与可控时间验证。

| 验证阶段 | 需要证明的事情 | 完成时留下什么记录 |
| --- | --- | --- |
| 模块测试 | 状态、排序、目录转换、引用、重试、参数保留等规则正确 | 对应代码提交、检查结果和未覆盖点 |
| 接口与并发测试 | 鉴权范围、批量原子性、并发停用/推荐、初始化重跑正确 | 请求与实际数据对照，失败分支结果 |
| 页面验收 | 管理页、目录、两套画布、引用跳转与实际提交一致 | 环境、代码版本、操作步骤、预期/实际和必要截图 |
| 真实 AI 联调 | BKFlow 应用有权限，指定模型能返回可处理的正常、空和错误样本 | 环境、模型、响应样本和结果，不记录密钥 |
| 目标环境验收 | 初始化和业务链路在交付环境中成立 | 指定空间、初始化前后核对、完整业务结果与剩余问题 |

开始任何测试或初始化前先核对实际数据库、缓存和外部服务地址。真实环境初始化、回退及业务调用按目标环境的操作授权执行。本地通过、CI 通过、真实 AI 联调和目标环境验收分别报告。

本页当前只记录计划。后续完成任务时，应补上实际提交和验证结果；暂定项未确认、真实联调未完成时，应如实保留对应缺口。

## 六、上线前的初始化与回退安排

| 顺序 | 要做的事 | 放行前确认 |
| --- | --- | --- |
| 1. 部署兼容能力、建立表结构 | 执行默认 migrate 建表 | 没有触发来源采集、存量回填或初始化任务 |
| 2. 预览存量初始化 | 用独立命令只预览指定空间或全部空间 | 核对原可选范围、旧 V4 关闭项、来源分类、老 API 诊断及旧范围限制例外 |
| 3. 手动执行初始化 | 逐空间保存目录、管理设置、旧配置快照与当前引用 | 失败空间可以重跑；成功空间不被回滚或重置 |
| 4. 接通各使用入口 | 管理页、两套画布、网关及保存检查统一接入 | 同一空间的列表、状态和拦截结果一致 |
| 5. 完成业务验收 | 回归存量编辑、建任务、启动、调试和新增拦截 | 记录目标环境证据，确认剩余暂定与联调事项 |

拟定命令为 `initialize_plugin_catalog`，参数及操作说明由任务 7、16 交付。该命令尚未实现，当前文档不代表已经运行迁移。

初始化过程失败时按空间回滚，其他成功空间保留。部署回退需要结合代码版本和数据快照检查；上线后已经产生的人工目录、推荐和启停决定，不能被旧配置快照静默覆盖。未完成初始化的空间继续原读取路径，并明确提示新管理功能尚未就绪。
